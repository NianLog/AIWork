# Agent Note: 两端共用的结构样式层 ui-tokens

Status: implemented

Scope: packages/ui-tokens/**,apps/portal/src/**,apps/admin/src/**

Last-verified: 2026-09-25

## Problem

2026-09-25 的版式重构（同一轮里把门户与后台的每个页面重排）暴露出一件前一版决定没预料到的事：**「不共享色板」并不等于「不共享骨架」**。

[钉钉组件库决定](2026-09-25-dingtalk-design-system.md)把 `styles.css` 的职责收窄为「骨架版式」，并明确两个前端不再共享样式包。这在只有一页半的时代是对的。页面铺开到 12 个之后，同一个骨架在两个应用里各写了一遍，且已经开始互相漂移：

- 应用卡片在门户叫 `.portal-appcard`，在后台是 `.dtd-table` 的单元格，两处的标题/副标题两级字号与行高不同；
- 页面标题区（`h1` + 说明 + 操作）在两个应用里的字号、间距、窄屏折行规则不同；
- 状态标签在门户是自研 `.portal-badge`，在后台直接用 `Tag`，同一个「试运行」两种视觉；
- 空状态、表单栅格、工具条这三类结构各写了一遍，其中门户表单栅格因为缺 `minmax(0,1fr)` 在窄屏溢出。

真正的代价不在样式重复，而在**两个应用对「同一个东西」给出不同答案**：读者在门户学会「试运行是橙色小标签」，到后台看到的是另一种形状。这类不一致没有单一真值来源，改一处不会改另一处，只能靠人记住——正是前一版决定否掉自研令牌层时想避免的那种成本。

## Decision

在 `packages/ui-tokens` 增加一层**只做结构与节奏、不做配色**的样式层，与前一版决定并存而非取代：

- `packages/ui-tokens/tokens.css` 定义 `--ui-*` 节奏令牌：间距阶梯、字号阶梯、字重、行高、字距、控件高度、圆角、动效时长与曲线、层级、页面留白。**颜色令牌（`--ui-brand`、`--ui-text-*`、`--ui-surface-*`、`--ui-line*`、`--ui-tone-*`）一律指向 `--common_*`（钉钉主题令牌）**。落地时有两处刻意的字面量例外：六个应用图标底色（violet / cyan / emerald / amber / rose / slate，钉钉色板里没有对应语义位）与 [品牌色 ED7D33 与主题令牌覆盖](2026-09-25-warm-brand-palette.md) 引入的 `:root:root` 覆盖块（主题色被指定为钉钉没有的色值）。两处都在注释里标注了理由。
- `packages/ui-tokens/components.css` 定义两端必须长得一样的结构件：版心、页头、卡片、标签、图标砖、行列表、事实表、统计卡、工具条、空状态、表单栅格、浮层遮罩与入场动效，以及**覆盖组件库默认值的双类选择器**（如 `.ui-card.dtd-card`）。双类是为了让特异性高于组件库自身的单类规则，不依赖打包顺序。
- 引入顺序固定为 `dingtalk-theme` → `ui-tokens/tokens.css` → `ui-tokens/base.css` → `ui-tokens/components.css` → 应用 `styles.css`，写在各 `main.tsx` 的 import 顺序里（顺序反了会拿到未定义的变量）。
- **2026-09-25 实测补一条此前没人写下来的隐藏条款：组件库的组件级 CSS 排在 `components.css` 与应用 `styles.css` 之间。** `es/` 产物的每个组件在自己的模块里 import 样式，这些 import 随着 `App`（第 9 行）进入模块图——于是顺序是「主题 → tokens → base → components → **dtd/dtm 组件样式** → 应用 styles」。后果：在 `components.css` 里按**同特异度**覆盖组件库（哪怕选择器一字不差），每次都会输；在应用 `styles.css` 里则同特异度就能赢。这是状态审计修桌面库禁用态时撞出来的（`.dtd-radio-disabled + span` 原样复制也覆盖不掉），证据：rgba(.24) 的禁用文字色在 components.css 里覆盖失败、加 `!important` 后 1.66→5.64。因此本层的分工细化为：**结构收敛放 `components.css`（靠双类提特异度，如 `.ui-card.dtd-card`），状态色覆盖也放 `components.css` 但必须带 `!important`**（焦点环、禁用文字、占位符文字三处先例），`styles.css` 里同特异度即可。别把这条当冷知识——它决定你写的覆盖生效还是不生效，而不生效的样子是「改了没反应、页面还是蓝灰色」。
- 两个应用的 `styles.css` 只保留**本应用独有**的东西：门户是工作台 hero 与宫格、应用卡片、详情浮层、子应用工作区条、登录分栏；后台是侧栏、顶栏、披露条与页标题行、统计卡、发布页专属区块、登录分栏。凡是两端都有的结构，一律引用 `.ui-*` 类，不得再自写一份。
- 组件选型、间距、圆角、配色的规范来源仍是钉钉组件库与 `dingtalk-theme`；`--ui-*` 只是把钉钉令牌整理成可复用的**节奏**，并（经上条那处例外之后）宣告品牌色的使用边界。

## 与「自研 shared-theme 被否」的关系（决策边界）

前一版决定否掉的是**自研色板 + 手搓组件库替代品**：`packages/shared-theme` 计划自己定义颜色、圆角、字号并重写卡片/抽屉/表格/分段筛选器。本次落地的东西不满足其中任何一条：

| 维度 | 被否的 shared-theme | 本次 ui-tokens |
| --- | --- | --- |
| 配色 | 自定义色板 | 引用 `--common_*`；仅重定义其语义位的取值，不新增语义位 |
| 组件 | 手搓卡片/抽屉/表格替代组件库 | 仍用组件库组件，本层只调它们的默认间距与边框 |
| 依赖方向 | 两个应用依赖它 | 两个应用依赖它，但它依赖 `dingtalk-theme` |
| 新增规范 | 新增一套与钉钉并行的视觉语言 | 不新增视觉语言，只统一两端已有的骨架 |

判据（原判据已被品牌色改动收紧）：**色值字面量只允许出现在 `tokens.css` 的 `:root:root` 覆盖块与 `--ui-*` 定义块，以及那六个图标装饰色。`base.css`、`components.css` 与两个 `styles.css` 里出现任何色值字面量都是越界。** 一旦有人在这些文件里造第二套色板，就等于把被否方案从后门放回来。

## Alternatives considered

- **继续各写各的 `styles.css`，只靠 review 对齐** — 这是前一版决定的默认路径，成本最低。否掉的原因已经发生过一次：漂移是渐进的，review 只看单个应用的 diff，看不到「两端对同一件事给了两种答案」。真要守住一致性，得有人同时记住 12 个页面的两种实现——比共享一个 CSS 文件贵得多。
- **把共享结构放进 `dingtalk-design-*` 的消费侧包装组件（`<UiCard>`、`<UiPageHead>`）** — 类型安全、可写单测、能防住「忘记加某个类」。否掉的原因是它把「改一个间距」变成「改组件 + 两个应用重新构建 + 可能撞上组件库 props 透传」，而这一轮的改动主体恰恰是间距与折行；另外新增的组件层会遮蔽钉钉组件本身的 props，长期收益不确定。样式层若将来真的撑不住（例如出现必须按 props 分支的骨架），再迁移到组件层，届时本笔记的 Scope 就是迁移清单。
- **只共享 `tokens.css`，结构件继续各写** — 能消掉「两个应用圆角/间距不一致」，但消不掉「同一件东西两种结构」。且本次发现的具体缺陷（空状态、表单栅格窄屏溢出、标签样式分叉）都在结构层，只共享令牌等于没修。
- **用 CSS Modules / 原子类方案统一** — 两个应用都是 Vite + 全局 CSS，引入一套原子类框架要动构建配置，且与钉钉组件库的类名体系并行，心智负担更高。收益（避免选择器冲突）在本项目规模下不成立：类名已全部带 `ui-` / `portal-` / `admin-` 前缀。

## Consequences

- **收益**：同一个结构在两端只有一处定义，改一次两端同时生效；新增页面时「页头怎么排、卡片怎么留白、空状态怎么写」不必再决定一遍。本次重构中，门户与后台的页头、卡片、统计卡、工具条、空状态、表单栅格、浮层动效全部收敛到同一定义，命名冲突也随之前置消灭（`ui-` 前缀由本层独占）。
- **收益**：颜色真值来源仍是唯一的。`--ui-*` 颜色令牌全部是 `--common_*` 的别名，钉钉主题换版时只需改 `tokens.css` 一处映射。
- **代价与已知上限**：多了一层需要维护的 CSS（`components.css` 目前约 1000 行）。它没有类型检查，写错类名不会报错，只能靠测试与 `scripts/qc/layout-audit.mjs` 兜。**出现下列信号时重访本决定**：① 有人需要在 `components.css` 里写 `--common_*` 之外的色值（越界信号）；② 覆盖组件库默认值的双类选择器数量持续增长（说明该改用包装组件）；③ 钉钉主题令牌改名（`--common_*` 是 beta 期命名，见前一版决定的代价一节）。
- **代价**：两个应用的 CSS 产物都包含完整本层（门户 130.81 kB，后台 409.65 kB，未 gzip），没有做按需拆分——两端结构件高度重合，拆分的收益低于维护成本。
