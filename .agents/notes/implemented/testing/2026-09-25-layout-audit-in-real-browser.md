# Agent Note: 用真实浏览器做版式审计，代替肉眼过页面

Status: implemented

Scope: scripts/qc/**

Last-verified: 2026-09-25

## Problem

[测试笔记](2026-09-25-vitest-dingtalk-esm-and-semantic-tests.md) 已经立过一条边界：jsdom 里 `matchMedia` / `ResizeObserver` 全是桩，一律 `matches: false`，**版式正确性无法在单测里断言，只能靠浏览器人工过**。

这条边界在 2026-09-25 的版式重构里变成实际风险：一次改了 12 个页面 + 1 个共享样式层，改动主体全是间距、折行、栅格与触控尺寸。人工过 19 个页面 × 两档宽度 = 38 次「打开、拖窗口、看、记住」，而且下一轮改动后要重来一遍。漏看一页的表现是某个窄屏页面上有一处横向溢出或者被裁掉的提示文字——这类缺陷不会让测试变红，只会让用户看到半句话。

另外两个具体问题在这次重构里真实发生过，肉眼几乎不可能发现：

- 组件库的 `NoticeBar` 描述行带 `-webkit-line-clamp: 2` + `overflow: hidden`，安全披露文案在窄屏折成四行时被裁掉后两行。截图上看是「一行正常的提示」，DOM 里是 `clientHeight 44 < scrollHeight 88`。
- 移动端 `SearchBar` 的内部输入容器钉死 30px，而输入节点自身要 34px，placeholder 下沿被父级裁掉。

## Decision

在 `scripts/qc/` 放四个一次性可复跑的审计脚本，用「几何事实」代替肉眼：

- `scripts/qc/layout-audit.mjs`：起一个 headless Chrome（`--remote-debugging-port` + 独立 `--user-data-dir`），通过 CDP `Emulation.setDeviceMetricsOverride` 逐页设成 1440×940 与 390×844，`Runtime.evaluate` 跑一段探测脚本，输出问题清单与每页关键数字。检查项：文档横向溢出、元素越出视口、内容高过盒子且被裁、`h1` 数量、`role="note"` 是否在场、`--ui-*` 令牌是否解析出值、基准容器是否存在、窄屏可点元素是否矮于 36px、**外框占用（见下）**。
- `scripts/qc/spacing-audit.mjs`：同一套 CDP 机制，量的是**纵向节奏**而不是边界。对每个容器比较同父级纵向相邻兄弟的 `gap = next.top - prev.bottom`：`gap < -0.5` 是真重叠（一定缺陷），`0 ≤ gap < 5` 是紧靠（多数正常，需逐条看）；另外列出负外边距的使用点与 `line-height < 1.25em` 的单行文字。它把「组件样式上下重叠/紧靠严重」这句反馈变成了可复读的数字：19 个页面 × 一个阈值，改完再跑一次就知道有没有回退。
- `scripts/qc/state-audit.mjs`：量**状态与色彩**——前两个脚本完全摸不到的一层。六项检查：① 每段可见文字的实际前景 vs 有效背景（半透明层叠加、祖先 opacity 压暗、渐变取全部色标做最坏情况）对 WCAG 4.5/3.0 线；② `cursor:pointer` 不够，还要**悬停真有反馈**——对每个语义可交互元素（a/button/role=button/menuitem/tabindex/分段项/自绘卡片）派发真实 mousemove，前后逐项比对 color/background/shadow/border/transform，零变化 = 死 affordance；③ 真实 Tab 走 12 站查焦点环可见性；④ 禁用态文字对比（< 2.5 判「过灰」，空输入框按 `::placeholder` 着色量）；⑤ 品牌色违规（`#ED7D33` 出现在文字色 / ≤2px 边框 / 伪元素细条 = 违反 tokens.css 的硬约束）；⑥ 全页色彩普查（每种不透明背景的占地面积）。它的豁免清单与阈值全部写进脚本注释：当前页链接（aria-current）与已选中项（段选/菜单 selected）的死悬停是**正确行为**；disabled 按钮无悬停反馈也是；中心点被遮罩或交互子元素占据的候选直接跳过（裁决用 `elementFromPoint(中心).closest(交互选择器) === 候选`）。
- `scripts/qc/css-probe.mjs`：单点深挖工具。给定 URL + 选择器，用 `CSS.getMatchedStylesForNode` 打印「哪份样式表的哪条规则最终生效」并递归打印盒模型与 `scrollHeight/clientHeight`。是它把上面那个 `line-clamp` 定位到组件库 `notice-bar/style/index.css` 的。

`state-audit.mjs` 首跑抓到、且**只有它能抓**的三件事（几何审计与测试全绿）：hero 的品牌渐变往深走，ink 文字在深端只有 2.09–2.37:1（整张卡文字不合格）；区块链接「全部应用」用了品牌橙做文字色 2.54:1；桌面/移动组件库的禁用态把文字压到 `rgba(23,26,29,.24)` ≈ 1.65:1——「暂未开放/登录开通后可用」这类**披露文案本身读不出**。它还连带挖出两个结构雷：入场动画的 `transform` 残留把 fixed 浮层困进内容盒（见[门户外壳笔记](../architecture/2026-09-25-portal-shell-and-subapp-workspace.md)），组件库 CSS 的注入顺序夹在 `components.css` 与应用 `styles.css` 之间（见[共享样式层笔记](../architecture/2026-09-25-shared-structural-style-layer.md)）。

另有 [类名交叉核对](2026-09-25-css-class-crosscheck.md)：那一篇解决的不是几何问题，而是「CSS 与 JSX 的类名是否还对得上」——重写样式层时它是唯一能发现「整块结构件忘了搬过来」的手段。

两条纪律：

- **审计脚本只读取，不改代码、不写产物**（`shoot.mjs` 除外：它只往 OS 临时目录写 PNG，供人眼终审）。它们不接入 `pnpm verify` / CI——CI 里没有浏览器，且这个审计是「改完版式后跑一次」的工具，不是每次提交都要跑的门禁。跑它的时机写在[共享样式层笔记](../architecture/2026-09-25-shared-structural-style-layer.md)的 Verification 一节。
- **审计的阈值与豁免必须写进脚本注释。** 触控目标阈值取 36px（WCAG 2.2 AA 的 Target Size 最低是 24×24，Apple HIG 建议 44，组件库默认 34）。刻意放在视口外的元素（视觉隐藏的跳过导航、窄屏滑出的侧栏、遮罩、抽屉）与单行省略号是豁免项，各自在代码里注明理由——否则审计会变成噪音，跑两次就没人看了。

当前基线：19 个页面组合（门户 4 页 + 登录 + 兜底 + 子应用工作区 3 态，后台 6 页 + 登录/兜底，含窄屏与平板档），三个审计脚本的问题清单都为空（真重叠 0、行高过紧 0、横向溢出 0、内容被裁 0、触控目标不足 0、对比度不达标 0、品牌色违规 0、死悬停 0、隐形焦点环 0）。19 是「探测脚本返回了结果」的页面数，不是测试断言数。

`spacing-audit.mjs` 在本轮抓到的两个真实缺陷，都是肉眼看不出、几何上一目了然的类型：

- 后台**每一个**页面的卡片都报 `gap = -1px`：组件库的 `.dtd-card-head` 带 `margin-bottom: -1px`，与 `.dtd-card-body` 真实重叠 1px。修法是在 `components.css` 里用双类选择器把它归零。
- 表格里每一列的版本号与日期都报 `font = 28px`：`.ui-num` 里写死了字号，而这个类同时被统计卡（要大号）与表格单元格（要正文大小）使用。修法是把字号从 `.ui-num` 移出，交给 `.ui-stat__value`。

### 外框占用检查（后来补上的第 6 项）

前五项都查不到的一类缺陷：**外框自己变高了**。它的成因是「某个内部容器少了 `display: flex`，于是几个子元素各占一行」，或者「宽度被挤，文字折成三行把父级顶高」。这类缺陷不影响溢出与裁切、不产生重叠、触控目标也正常，唯一的表现是顶栏比设计高——肉眼只看到「顶栏好像有点高」，量不出 40px 与 95px 的差别。

本轮它一次抓到三处：

| 位置 | 实测 | 应然 | 成因 |
| --- | --- | --- | --- |
| 门户外壳顶栏 | 95px | 40px | `.portal-appbar__inner` 少了 `display: flex`，品牌 / 导航 / 身份各占一行，95 ≈ 三者高度之和 |
| 后台顶栏（手机） | 85px | 40px | 390px 下面包屑被挤到 30px 宽，「平台管理 / 应用列表」竖折成三行共 84px |
| 后台顶栏（手机） | 45px | 40px | 操作人链接多给了 4px 上下内边距，44px 的两行内容把 40px 顶栏撑高 |

判据是**自洽**的：每个外框元素的实际高度不得超过**它自己声明的 `min-height`** + 4px。不去读令牌名，是因为「这个元素该多高」本来就写在它自己的样式里（`.ui-appbar` 用 `--ui-appbar-h`、`.workspace__bar` 用 `--ui-workspacebar-h`），脚本再维护一份「选择器 → 令牌名」的映射只会多一处会写错的地方。4px 余量留给 1px 边框与行盒取整。

当前实测：门户顶栏 41/49px（声明 40/48）、门户标题行 28px（声明 28）、后台顶栏 40/48px（声明 40/48）、子应用工作区条 37px（声明 36）。

两条阈值纪律（否则跑两次就没人看了）：

- `gap` 在 0~5px 之间默认算「紧靠」，但**贴边与单元格本来就是 0px**：容器首个子元素贴着内边距上沿、表格行之间只有 `padding` 没有 `gap`。所以紧靠是待判清单，不是缺陷清单；只有 `gap < 0` 判红。
- 比较「同父级纵向相邻兄弟」时要先排除 **DOM 顺序与视觉顺序不一致** 的情况：grid 自动排布会把整行的项插在中间，于是「DOM 里的前一项」在视觉上位于后一项的**下方**，算出 -126px 这样的荒谬负值。判据是「前一项的顶边必须确实在后一项顶边之上（容差 1px）」，否则跳过。发布页的 `.ui-field--full` 最初就是这样被误报的。

## Alternatives considered

- **继续靠人工过页面** — 零新增代码，且人的眼睛能发现审计覆盖不到的问题（视觉重心、配色是否舒服）。否掉的原因是它不可复跑、不可交接、不留下任何证据，而且这次真正踩到的两个缺陷恰好是「肉眼看不出但几何上一目了然」的类型。人工过页面仍然要做，只是不再作为唯一手段。
- **引入 Playwright / Puppeteer 写真正的视觉回归测试** — 能截图对比、能录视频、生态成熟。否掉的原因是它要给仓库增加一个重量级依赖（含浏览器二进制下载）与一套基线图管理流程，而本项目的版式仍在快速变动期——基线图每周都要重拍，维护成本会超过收益。CDP 裸连不需要任何新依赖。
- **用 `--dump-dom` / `--screenshot` 这类纯 CLI 手段** — 无依赖、一行命令。否掉的原因是 CLI 只能拿到「渲染后的 HTML 文本」或一张图，拿不到 `scrollWidth`、`scrollHeight`、`getBoundingClientRect` 这些几何量——而本笔记开头的两个缺陷都只体现在几何量上。另外本环境当前模型不支持读图，「看截图」这条路在这一轮本来就走不通。
- **把审计做成 Vitest 里的 jsdom 断言** — 能进 CI。否掉的原因是 jsdom 没有真实布局引擎，所有元素 `getBoundingClientRect()` 都是 0，测不出溢出与裁切。

## Consequences

- **收益**：版式回归从「38 次人工检查」变成一条命令，且结论可复读（问题清单 + 每页数字）。这次重构结束时它是唯一能证明「19 个页面都没有横向溢出、没有内容被裁、每页恰好一个 `h1`、令牌确实生效」的手段。
- **收益**：`css-probe.mjs` 把「某个属性为什么是这个值」的排查从猜测变成事实。组件库的类名、`line-clamp`、钉死高度这类坑，看一眼匹配规则就定位了。
- **代价与已知上限**：审计跑的是 dev server（5173/5174），**必须先起服务**，且默认端口硬编码在脚本里；CI 里跑不了，所以在 CI 绿与版式正确之间没有机械保证。阈值是启发式的：36px 触控线、±1px 的溢出容差都可能漏掉「差一点点」的问题，屏幕阅读器顺序、对比度、动效是否舒适也完全不在覆盖范围内。
- **代价**：`--hide-scrollbars` 会让 `window.innerWidth` 在窄屏档报 417 而不是 390（脚本按 390 设的指标，但滚动条占位仍计入）。数字看起来对不上是预期现象，不影响溢出判定（判定用的是 `documentElement.scrollWidth` 与 `innerWidth` 的一致性）。
- **触发重访的信号**：① 审计连续两轮问题清单为空但人工仍然发现视觉缺陷（说明检查项不够）；② 版式进入稳定期（可以换成真正的视觉回归基线）；③ 上线 CI 需要版式门禁（需要把浏览器装进 CI 镜像）。
