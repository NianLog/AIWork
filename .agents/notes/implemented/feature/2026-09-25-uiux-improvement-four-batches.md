# Agent Note: 门户与后台体验改进四批次（四态骨架 / URL 状态 / 彩虹规范 / 表格交互）

Status: implemented
Scope: packages/ui-tokens/**,apps/portal/src/**,apps/admin/src/**
Last-verified: 2026-09-25

## Problem

钉钉组件库重写（见 [2026-09-25-dingtalk-design-system](../architecture/2026-09-25-dingtalk-design-system.md)）落地后，
可用性审计留下五类缺口：加载与失败形态缺失（页面只有成功态）、详情浮层状态不在地址上
（不可分享、返回键语义混乱）、行内操作是三个无文字的禁用图标按钮（禁用态下读不出语义）、
统计卡与表格是两张皮（数字不能点）、工作台首屏下半页被一张「暂无数据」说明卡占据。
另外项目文化主题「让生活更多彩」要求加载类组件用七彩色块，需要一个不破坏品牌纪律的实现方式。

## Decision

四个批次一次做完，全部落在既有分层里（页面认数据形状、令牌进 tokens.css、结构件进 components.css）：

1. **四态数据视图契约**：`DataView<T> = { status: 'loading'|'error'|'success'; data: T[]; error?: string }`，
   演示数据是永远 success 的来源；loading 骨架与 error（标题 + 原因 + 重试）分支由测试喂形状覆盖，
   不造假的加载延迟——假装在加载比没有加载更糟。P0-4 接真实接口时只换来源。
2. **选中态进 URL**：详情浮层开关是 `?app=<appId>`。打开推历史（浏览器返回 = 关浮层），
   关闭用 replace（关掉之后再按返回不会重新打开），详情地址可深链分享。
3. **彩虹规范**（负责人 2026-09-25 批准）：7 个 `--ui-rainbow-*` 令牌，橙色位就是品牌色本身；
   只用于装饰位——加载骨架微光条 / 加载指示条 / 空态点缀；不进文字、链接、按钮、徽章、焦点环、边框；
   块宽 ≥8px；单屏 ≤2 个色相；骨架本体仍是单色淡染 + shimmer，彩虹只是点缀。
   reduced-motion 全局开关沿用 base.css 既有的那一个。
4. **工作区舞台立契**：`WorkspaceStage` 四态（loading / error / ready / not-integrated）在接 iframe 之前
   就把契约定住；演示 entry 是 RFC 2606 保留域，当前恒为 not-integrated（说明 + 返回出口），
   P0-4 只换状态来源，舞台与布局不改。
5. **后台表格交互**：统计卡改成真按钮（点卡片切口径，aria-pressed 表达选中）；
   默认排序列（应用按最近更新、用户按最近登录且「从未登录」最旧、角色/组织按人数）；
   分页 10 条且单页隐藏；行操作收敛为「文字主操作 + ··· 下拉」，禁用项把原因写进可访问名与悬停提示。
6. **工作台下半页**：使用数据的空说明卡换成「功能进展速览」，与功能进展页共用 `store/roadmap.ts`
   一份数据；hero 指标之间加分隔线、数字放大（数据组结构化）。

## Alternatives considered

1. **全局 toast 反馈**——推迟。当前没有任何真实写路径，toast 没有调用点；先立契约（写操作一律禁用 + 原因），
   等第一个真实写操作（P0-3 起）落地时随错误处理一起设计。
2. **表格批量操作（多选 + 批量停用）**——推迟。演示数据只读，多选框全禁用只会增加噪音；
   等真实写接口就绪后随列表页一起评估。
3. **图标全面彩色化**——维持既有折中。6 个色相、8-12% 淡染底 + 同色相深字已是当前状态，
   审计通过；彩虹只做加载/空态装饰位，不扩大战场。

## Consequences

- 演示数据模块（demoCatalog / demoDirectory）新增 `*_VIEW` 常量与 DataView 接口，P0-3/P0-4
  删除演示模块时页面组件不改形状，只换来源。
- `filterDemoApps` 仍读全局演示数组（市场页成功态专用）；换真实来源时随调用点一起改。
- 彩虹橙色段（#ed7d33）作为品牌色块出现于 `.ui-rainbow-bar`，已确认不触发状态审计的品牌色违规线
  （块状装饰位是品牌色硬规则的允许用法）。
- 待办随批带走：子应用身份注入契约（门户向 iframe 传什么）没有文档，P0-4 容器层开工前必须补一篇
  architecture 笔记定约，`WorkspaceStage` 的 ready 分支（sandbox / allow 属性）在那篇笔记里定稿。
- 测试面新增三个文件/用例组：门户 URL 抽屉（深链 + 返回关闭）、市场加载态（mock 注入）、
  工作区舞台四态直渲染；后台补统计卡筛选与默认排序断言。

  判定通过（对比度 0、品牌色违规 0、悬停无反馈 0、焦点环不可见 0）。
