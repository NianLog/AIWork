# 子应用接入规范（平台开放能力）

> 面向在本平台（AIWork 门户）上接入子应用的开发者。本文只描述**已实现并已上线**
> 的能力与契约；未实现的能力明确标注前置条件，不承诺时间。

## 1. 平台提供什么

| 能力 | 状态 | 入口 |
|---|---|---|
| 身份共享（登录态/令牌/权限判断） | 已上线 | 容器注入的 `PortalHandle`（SDK） |
| 权限码体系（应用自有按钮级权限） | 已上线 | `micro-app.config.json` 的 `permissions` |
| 平台通知（站内信必达 + 钉钉工作通知） | 本批上线 | `POST /admin-api/portal-notification/app-send` |
| 钉钉免登（子应用内免密进钉钉身份） | 未实现 | 前置：门户域名公网可达（备案/DNS 就绪） |
| 钉钉收消息（Stream 模式） | 未实现 | 无公网回调要求，但本批未做 |

身份与权限码的接入方式（SDK 原语、manifest 声明、RBAC 授权链）见
[AI中台宿主门户_开发引导文档](./AI中台宿主门户_开发引导文档.md)与 `apps/demo-vue` 示例；本文只展开通知能力。

## 2. 通知能力契约

子应用**不直接持有任何钉钉凭据**。发送一律经平台统一端点，以「当前登录
用户」的身份调用（用户态），平台负责权限校验、站内信落库与钉钉通道投递。

```
POST /admin-api/portal-notification/app-send
Content-Type: application/json
tenant-id: 1
Authorization: Bearer <SDK 现取的访问令牌>

{
  "appId":  "demo-vue",       // 服务端强制取自调用方注册身份，请求体可不传语义上无效
  "userId": 7,               // 收件平台用户编号
  "title":  "任务完成",        // ≤128 字
  "content": "你提交的视频已生成完毕",  // ≤1024 字
}
```

字段校验与错误码（CommonResult 信封，`code` 为业务码）：

| HTTP | code | 含义 | 子应用应对 |
|---|---|---|---|
| 401 | — | 登录态失效 | 重新走 SDK `getToken()`（内部自刷新） |
| 403 | — | 当前用户无 `portal:notify:app-send` 权限 | 引导找管理员授权，勿重试 |
| 200 | `1_100_007_001` | appId 不存在或应用已停用 | 检查应用注册状态 |
| 200 | `1_100_007_002` | 收件用户不存在或已停用 | 修正 userId |

行为语义：

- **站内信必达**：收件人站内信列表逐人一行，是通知的事实源。
- **钉钉工作通知尽力而为**：通道启用且该用户已在后台完成「钉钉绑定」时同步
  私发；未绑定/通道未启用/钉钉侧失败均不影响站内信，调用方无感知差异。
- **来源可追溯**：落库 `bizType = "app:{appId}"`，站内信列表按此过滤与跳转。
- **量限**：钉钉对企业工作通知有日发送量限与频控，超限时该通道当日降级为
  仅站内信（平台日志留痕），不是错误。

## 3. 钉钉能力边界（务必读）

- **工作通知（发）**：链路已实现并通过协议桩测试，但企业凭据（AppKey/
  AppSecret/AgentId）配置前通道保持关闭——**桩测试 ≠ 真实送达已验证**。
  凭据到位后的启用流程见 `DEPLOY.md` 第七节。
- **绑定是前置**：用户须先在后台「钉钉绑定」页完成 平台用户 → 钉钉 userid
  映射，工作通知才会私发到人；未绑定用户只收站内信。
- **免登（登录态互通）**：需要门户域名公网可达。当前 DNS/备案未就绪，推迟。
- **收消息（Stream 模式）**：钉钉 Stream 模式不需要公网回调 URL，技术上
  可行，但平台侧未实现，子应用暂勿设计依赖收消息的流程。

## 5. 上线 checklist

1. `micro-app.config.json` 的 `permissions` 声明 `portal:notify:app-send`；
2. 应用经后台上架/发布（存在且启用，否则发送被 `1_100_007_001` 拒绝）；
3. 管理员在「角色管理」为目标角色勾选该权限码（RBAC 生效链同其他按钮权限）；
4. 收件用户完成钉钉绑定（需要钉钉送达时）；
5. 发送侧永远现取 SDK token、不缓存、不吞错误——403/业务码原样呈现给使用者。
